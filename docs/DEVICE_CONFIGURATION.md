# 장비 등록·공유 연결·역할·권한

장비·연결·역할 식별자는 앱에서 생성한다. 이름을 바꾸거나 같은 장비를 편집해도 장비 ID는 유지하며,
장비 ID는 장비 진단에서 확인한다. 장비 제어·시나리오·권한 선택에는 이름과 위치·연결 정보를 사용한다.

## 등록과 PC 선택

- 관리자 설정에서 새 장비 등록 → 이름·위치·모델 → 연결 선택 또는 생성 → 장비 설정 저장.
- 저장 시 기본 역할을 함께 생성한다. 역할을 사전에 만들 필요 없이 장비 조작과 시나리오에서 선택할 수 있다.
- 모델의 `RequiresTargetPc`가 참인 PC 장치에만 대상 PC를 표시한다. 저장 시 ID와 이름은 `PcRegistration`에서 가져온다.
- 일반 장비의 기존 PC ID·이름과 가상 값 키를 보존한다. 신규 일반 장비에는 대상 PC를 자동 배정하지 않는다.
- 특정 PC의 포트를 쓰는 통신은 `ExecutionPcTransportIds`에 선언하고 공유 연결의 `ExecutionPcId`를 선택한다.
  대상 PC와 통신 실행 PC는 서로 다른 설정이다.
- 새 PC 등록은 해당 PC 앱으로 로그인한 관리자가 ‘이 앱 PC 등록 · 이름 갱신’을 사용한다.
  현재 실제 PC 장치 드라이버·DeviceAgent 연동은 후속 범위다. 등록만으로 장치 탐색·제어 가능을 보장하지 않는다.

## 공유 연결

`SharedDeviceConnection`은 앱 생성 ID, 연결 이름, 편집 버전, 통신 방식·실행 PC·접속 주소·공통 옵션을 보관한다.
장비는 연결 ID를 참조하고 장비 주소·채널·드라이버 옵션을 별도로 보관한다.

- 통신 방식부터 선택하면 현재 모델의 선언과 허용값에 맞는 연결을 보여 준다.
- ‘전체 연결에서 먼저 선택’으로 연결을 먼저 고르면 통신 방식·설정과 호환 모델을 채운다.
- 호환되지 않는 통신 방식·모델로 변경하면 기존 연결 선택을 해제한다.
- 기존 연결 사용 중 공통 필드는 읽기 전용이다. ‘공유 연결 수정’으로 편집을 열고 영향받는 장비 목록을 확인한다.
- ‘이 장비용 새 연결로 저장’은 설정을 복사해 새 ID를 만든다. 원래 연결과 다른 장비는 유지한다.
- 이름·통신 방식·접속 주소가 같더라도 새로 만든 연결을 자동 병합하지 않는다.
- 공유 변경은 관련 장비 모두를 드라이버와 저장 시나리오 요구사항으로 검증한 후 한 트랜잭션으로 반영한다.
  하나라도 호환되지 않으면 전체 변경을 거절한다. 오래된 장비/연결 편집 버전도 거절한다.
- 실행 설정 변경은 관련 장비의 실행 버전을 증가시킨다. 접수 작업 snapshot은 변경하지 않으며,
  다음 전송 전 검증에서 변경을 감지해 중단·재검토한다. 이름·위치 변경만으로 실행 대상을 무효화하지 않는다.

## 드라이버 설정 항목

`DeviceModel.Settings`의 `DeviceSettingDefinition`으로 입력·기본값·필수 여부·정수 범위·선택값·고정값을 선언한다.
`TransportId`를 지정하면 해당 통신 방식에서만 표시·검증한다.

| 저장 대상 | 선언 |
|---|---|
| 공통 접속 주소 | `Endpoint` |
| 포트·통신 속도 등 공통 옵션 | `ConnectionOption` |
| 장비 주소 | `Address` |
| 채널·장비별 옵션 | `DriverOption` |

텍스트·정수·선택 목록·논리값 입력을 제공한다. `FixedValue`는 앱이 채우고 편집을 막는다.
사전에 정의되지 않은 제조사 포트·속도를 추정하지 않는다. 현재 가상 드라이버에는 물리 입력 항목이 없다.
옵션 사전 구조는 유지하므로 기존 확장 옵션을 일반 편집 때문에 지우지 않는다.
비밀번호·토큰은 옵션 스키마에 넣지 않고 해당 드라이버의 보호 저장 경로를 사용한다.

## 테스트·진단과 역할 관리

가상 장애와 지연은 ‘장비 진단’에서 현재 값을 불러온 뒤 별도로 저장한다.
가상 장비에만 쓰기를 허용하고 장애 주입 중에는 장비 목록·조명 카드에 표시한다.
일반 등록·편집은 기존 진단값을 보존한다. 물리 드라이버 경계에는 가상 장애·지연을 전달하지 않는다.

역할은 한 장비만 가리킨다. 신규 기본 역할의 표시 이름은 장비 이름을 따른다.
**장비 제어 → 장비 목록 · 상세 조작**에서 장비를 선택하고 **새 역할 이름 → 역할 생성 · 추가**를 누르면
역할을 생성해 선택 장비에 바로 배정한다. 입력란과 버튼은 상세 영역 맨 위에 표시하며 기존 역할은 유지한다.
**관리자 설정 → 역할 관리 · 장비 교체 → 새 역할 생성**에서는 장비 선택 없이 이름만으로 미배정 역할을 만든다.
생성한 역할은 관리·배정 목록에 자동 선택된다. 아래에서 장비를 선택하고 **선택 장비가 기존 역할 이어받기**로 배정한다.
이름은 1~120자로 입력하며 앞뒤 공백을 제거한다. 생성 성공 후 입력란을 비우고, 실패 또는 주기 갱신 시 입력 중인 이름을 유지한다.
장비에 바로 생성·배정한 역할은 장비 조작에서 자동 선택되며 시나리오에서도 사용할 수 있다.
기존 역할은 선택 장비에 이어받는다.
배정 해제 시에도 ID·이름·삭제 버전을 보관해 ‘미배정’ 목록에서 다시 선택할 수 있다.
시나리오 참조와 기존 역할 ID는 유지한다. 여러 장비의 일괄 조작은 기존 그룹 기능을 사용한다.
관리자 설정 맨 위에 역할 관리를 기본으로 펼쳐 표시한다. 중첩 펼침 메뉴 없이 새 역할 생성과 기존 역할 선택·이름 입력·수정·삭제 버튼을 함께 제공한다.
**기존 역할 수정 · 삭제**에서 배정·미배정 역할의 이름을 수정한다. 기본 역할을 직접 이름 변경하면 이후에는 지정한 이름을 사용한다.
이름만 바꿀 때는 배정 버전과 시나리오 참조·접수 작업 snapshot을 보존한다.
장비에 배정된 역할은 삭제할 수 없다. 먼저 배정을 해제하고, 저장 시나리오의 참조와 진행 중 작업을 정리한 뒤 삭제한다.
삭제는 장비·실행 이력을 유지하며, 삭제한 역할은 재시작 시 미배정 목록에 복원하지 않는다.
역할 생성·배정·수정·삭제에는 관리자 사용권이 필요하다. 장비 없는 미배정 역할 생성은 최신 ControlHost에서 지원하며 구호스트에 연결하면 업데이트 안내와 함께 비활성화한다. 다른 수정·배정 변경을 감지하면 다시 불러오도록 안내한다.
장비 카드의 역할 미배정 표시는 유지하고 하단의 중복 배정 안내는 표시하지 않는다.

## 계정 권한

‘전체 장비’는 앞으로 추가되는 장비도 포함한다. ‘선택한 장비만’은 체크한 장비 ID 집합만 저장한다.
현재 목록을 전부 체크해도 전체 권한으로 전환하지 않는다. 새 장비는 제한 목록에 자동 추가하지 않는다.
목록 갱신은 편집 중 선택을 보존하며, 목록에 없는 기존 권한도 임의로 삭제하지 않는다.

Hiperwall 정책은 유지한다. 활성 관리자/운영자 + 전체 장비 범위일 때 제어 허용 조건을 충족하며,
실제 제어에는 사용권과 Hiperwall 연결·쓰기 가능 상태도 필요하다. 저장된 범위와 반영할 범위를 구분해 표시한다.

## 기존 데이터와 저장

SQLite 테이블 형식은 유지하고 payload의 `DeviceConfigurationVersion=1`에서 연결·PC 목록을 도입한다.
기존 연결 ID와 정확한 공통 설정이 같은 경우만 동일 연결로 이관한다. 동일 ID의 공통 설정이 충돌하면 별도 연결로 분리하고
기존 ID는 `LegacyConnectionId`에 보관한다. 이름이나 통신 방식만으로 병합하지 않는다.
장비 ID·PC 정보·상태·계정 범위·역할·시나리오·작업 snapshot을 보존한다.

등록 장비의 공통 연결 설정은 저장 시 제거하고 연결 목록에 한 번만 저장한다. 조회·실행 시 참조를 해석한다.
접수 작업은 접수 당시의 완전한 설정을 별도 snapshot으로 보존한다.
연결이 분리된 오래된 작업은 대상 검증에서 재검토할 수 있으며 다른 연결로 자동 전환하지 않는다.
새 payload 저장 후 구버전 호스트로 되돌리는 것은 지원하지 않는다. App과 ControlHost를 함께 배포한다.

관련 구현: Core `DeviceConfiguration`, Application `DeviceConfigurationService`, App `DeviceConfigurationViewModel`·
`DeviceRegistrationView`, Infrastructure `SqliteStateStore`.
검증: `DeviceConfigurationTests`, `DeviceConfigurationViewModelTests`, WPF `DeviceDriverSettingsSmoke`와 전체 회귀.
