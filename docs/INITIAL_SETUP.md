# 초기 설정 상태와 저장 위치

설치 프로그램에서는 설치 위치·바로가기만 선택하고, 완료 후 앱을 실행해 초기 설정을 이어간다.
서버 연결·데이터 폴더·영상 설정은 앱에서 지정하며, 나중에 연결이나 위치를 바꾸기 위해 재설치할 필요가 없다.

접속 설정과 기존 데이터가 없는 첫 실행에는 **새로 시작 / 기존 서버 접속 / 기존 데이터 사용** 선택 화면을 먼저 표시한다.
저장된 로컬·원격 접속 설정이 있는 사용자는 이 과정을 건너뛰고 로그인한다. 기존 데이터·설정 오류는 새 설치로 취급하지 않으며 로그인 화면의 복구 안내를 유지한다.
설정을 다시 열려면 로그인 화면의 **초기 설정 · 저장 위치**를 사용한다.

| 시작 방식 | 이어지는 동작 |
|---|---|
| 새로 시작 | 저장 위치·현장·관리자 계정을 입력한다. 서버 생성과 설정 저장 후 서버 실행을 승인하면 입력한 관리자 계정으로 바로 접속한다. |
| 기존 서버 접속 | 주소·인증서 지문을 저장한 뒤 기존 앱 계정으로 로그인한다. |
| 기존 데이터 사용 | 기존 폴더를 검증하고 연결한 뒤 그 데이터의 앱 계정으로 로그인한다. |

사용 방식을 다시 선택할 수 있으며, 방식 전환·뒤로 가기·완료·닫기 시 관리자 비밀번호 입력을 지운다.
상태 표시와 서버의 실제 실행·접속 성공은 별개다. 로컬 서버 실행은 저장 후에도 기존 실행 확인 절차를 따른다.

| 표시 상태 | 의미와 다음 동작 |
|---|---|
| 초기 설정 필요 | 접속 정보와 기존 데이터가 없으면 새 서버 생성, 기존 데이터 연결, 원격 서버 중 선택한다. |
| 기존 로컬 데이터 | 지정 폴더의 필수 파일·DB 헤더·공개 인증서를 확인했다. 경로 변경/재연결 시 호스트가 DB 초기화·스키마와 보호 인증서도 확인한다. |
| 원격 / 별도 서버 접속 | 운영 데이터는 접속 서버가 관리한다. 이 PC의 서버 시작을 끄며 데이터 폴더를 만들지 않는다. 수동 실행한 같은 PC 서버도 이 방식으로 접속할 수 있다. |
| 설정 오류 / 서버 준비 실패 | 손상 JSON, 경로·필수 파일 누락, DB 형식, 인증서, 접속 정보 불일치, 서버 시작 실패를 안내한다. 기존 데이터를 새 현장으로 대체하지 않는다. |

## 저장 위치

| 내용 | 기본 위치 / 결정 방법 |
|---|---|
| 접속 정보, PC ID, 최근 아이디 | %LOCALAPPDATA%\IntegratedContro\client.json |
| 화면 설정·초안 | 같은 사용자 프로필 폴더의 기존 파일 |
| 서버 시작 설정 | %LOCALAPPDATA%\IntegratedContro\server-startup.json |
| 새 로컬 서버 운영 데이터 | %LOCALAPPDATA%\IntegratedContro\HostData를 제안하며 **생성 전에 사용자가 확정하거나 변경** |
| 기존 로컬 서버 운영 데이터 | 사용자가 선택한 기존 폴더를 그대로 사용 |
| 원격 서버 운영 데이터 | 원격 호스트에서 지정한 폴더 |

현재 사용자용 기본값이며 Windows 서비스의 공용 데이터 위치를 정한 것이 아니다.
운영 DB·계정·작업·인증서·보호 파일은 호스트 데이터 폴더에 유지한다.
설치 폴더와 겹치는 위치, 상대 경로, 네트워크 공유, 이동식 디스크, 링크/재분석 지점은 새 선택에서 거부한다.
설정·폴더 접근 실패 시 기본 위치로 자동 전환하지 않는다.

## 새 로컬 서버

앱이 ControlHost 최초 설정을 실행하므로 PowerShell 실행이나 이 PC의 인증서 지문 수동 복사는 필요 없다.

1. 첫 실행 화면에서 **새로 시작**을 선택한다.
2. 빈 로컬 폴더, 현장 이름, 최초 관리자 아이디와 12자 이상 비밀번호·확인을 입력한다.
3. 필요한 경우 **서버 수신 주소 · 고급 설정**에서 수신 IP·HTTPS 포트를 지정한다. 기본 127.0.0.1:7443은 같은 PC 전용이다. 다른 PC 접속은 실제 수신 IP 또는 0.0.0.0과 현장 네트워크 정책을 별도로 설정한다.
4. **새로 시작 · 관리자 접속**을 누른다. 별도 ControlHost가 초기화하며 비밀번호는 표준 입력으로만 전달하고 저장하지 않는다.
5. 접속 주소·인증서 지문을 저장한 뒤 꺼진 서버의 실행 여부를 묻는다. 승인하면 방금 입력한 관리자 계정으로 바로 접속한다. 비밀번호를 다시 입력할 필요가 없다.

비밀번호는 이번 접속에만 사용하고 파일에 저장하지 않는다. 다음 실행부터는 저장된 관리자 아이디가 있는 일반 로그인 화면에서 비밀번호를 입력한다.
서버 실행을 거절하거나 접속에 실패하면 생성된 계정과 설정을 유지한 채 로그인 화면을 표시한다. 서버 상태를 확인한 후 기존 계정으로 접속하며 새 서버를 다시 생성하지 않는다.
접속 직후에는 기존 로그인과 동일한 조회 모드이며, 제어하려면 **사용 시작**을 선택한다.

기존 파일이 있는 폴더에는 생성하지 않는다. 초기화 후 설정 저장만 실패해도 해당 DB를 다시 생성하지 않고 기존 데이터 연결로 전환한다.
접속 설정·기존 데이터가 없는 신규 설치는 **영상 서버 사용**과 **자동 생성 · 연결 확인 (이 PC)**이 기본 선택된다. 주소·영상 계정·비밀번호를 따로 입력하지 않아도 함께 생성·등록한다. 영상이 필요 없으면 체크를 해제한다. App·ControlHost·MediaMTX가 함께 있는 배포 구성을 사용한다. 저장된 기존 사용 여부는 자동으로 바꾸지 않는다.

## 영상 서버 최초 설정

1. 새 로컬 서버 생성 또는 **기존 데이터 사용**에서 **영상 서버 사용**을 확인한다. 신규 설치는 기본으로 켜져 있다. 기존에 영상 사용을 꺼 둔 호스트에 추가할 때는 직접 켠다.
2. 기본은 **자동 생성 · 연결 확인 (이 PC)**이다. 포트나 기존 파일 방식을 바꿀 때만 **영상 서버 · 고급 설정**을 펼친다.
3. API/HLS/RTSP 포트를 확인한다. 기본값은 각각 9997/8888/8554이며 서로 달라야 하고 ControlHost 포트와도 겹치면 안 된다.
4. 설정 저장을 누르면 ControlHost가 서로 다른 API/HLS 전용 비밀번호를 생성하고 설정 파일을 작성한다. 임시 MediaMTX를 실행해 API 인증·경로 등록/삭제 권한, HLS 읽기 인증, 익명 접근 차단과 계정 권한 분리를 확인한다.
5. 확인이 성공하면 같은 주소·계정을 ControlHost에 등록하고 앱의 서버 시작 설정을 저장한다. 임시 서버는 종료하며, 이어지는 서버 실행 질문에서 **예**를 선택하면 운영 서버를 시작한다.
6. 접속 후 **카메라 · 영상 → 영상 서버**에서 호스트의 주소·계정이 자동으로 표시된다. 조회 모드와 다른 PC에서도 같은 설정을 사용하며 비밀번호를 입력하거나 설정을 다시 저장할 필요가 없다. 카메라 등록과 실제 입력·재생 확인은 별도로 진행한다.

로그인 후 영상 서버 화면에 **호스트 영상 서버 설정 필요**가 나오면 호스트 DB에 영상 설정이 아직 등록되지 않은 것이다. 기존 로컬 서버에 영상을 추가할 때는 앱이 시작한 ControlHost·MediaMTX를 앱 정상 종료로 함께 종료하고, 다시 실행한 앱의 서버 시작 질문에서 **아니요**를 선택한다. 로그인 화면의 **초기 설정 · 저장 위치 → 기존 데이터 사용**에서 기존 데이터 폴더를 유지한 채 **영상 서버 사용**을 켜고 자동 생성으로 저장한다. 수동으로 실행한 서버는 먼저 별도로 정상 종료한다. 기존 현장·계정·카메라 목록을 유지하며 영상 주소·계정·비밀번호를 다시 입력할 필요가 없다.
자동 생성은 동일 PC의 loopback 연결을 사용한다. 다른 PC의 앱은 HTTPS ControlHost를 통해 영상을 조회한다. 다른 PC에서는 기존 서버 접속으로 ControlHost 주소·인증서 지문을 지정하고 로그인하면 된다. MediaMTX 설정 파일이나 비밀번호를 클라이언트 PC에 복제하지 않는다.

영상 서버 화면은 조회 중·설정 필요·자동 사용·조회 실패·호스트 연결 대기·적용 확인 필요를 구분한다. 자동 사용은 저장된 설정을 사용한다는 뜻이며 실제 카메라 재생 성공을 보장하지 않는다. 관리자 고급 설정은 기본으로 접혀 있고, 외부 서버 수동 등록과 자동 생성 서버의 비밀번호 변경을 제공한다. 편집 중에는 자동 조회가 입력을 덮어쓰지 않는다. 호스트 설정 버전이 바뀌면 저장을 막으며, 고급 설정을 닫고 다시 열면 최신 설정으로 편집한다. 호스트 또는 로그인 세션이 바뀌면 이전 설정·편집·비밀번호 입력을 지운다.

| 생성/저장 항목 | 위치와 내용 |
|---|---|
| MediaMTX 설정 | 선택한 운영 데이터 폴더의 MediaMTX/mediamtx.yml. API/HLS 전용 계정의 비밀번호 해시만 기록 |
| 자동 설정 복구 기록 | 같은 MediaMTX 폴더의 setup.json. 포트·보호 참조만 기록 |
| API/HLS 비밀번호 원문 | 운영 데이터 폴더의 media-*.dpapi에 현재 Windows 계정으로 보호 |
| ControlHost 영상 접속 정보 | 기존 control.sqlite에 주소·사용자 이름·보호 참조 저장 |
| 앱 서버 시작 설정 | 기존 사용자 프로필의 server-startup.json에 실행 파일·설정 경로·API 주소 저장 |

비밀번호는 화면·명령행·일반 설정 파일·로그에 출력하지 않는다.
[MediaMTX 1.21 인증 규약](https://github.com/bluenviron/mediamtx/blob/v1.21.0/docs/2-features/06-authentication.md)에 맞춰
256비트 난수 비밀번호의 SHA-256 해시를 Base64로 기록한다.

기존 파일·등록된 다른 영상 설정·실행 중인 서버는 덮어쓰거나 종료하지 않는다.
수동으로 준비한 서버는 **기존 설정 파일 사용**을 선택하고 관리자 화면의 영상 설정을 유지한다.
앱이 생성한 로컬 서버의 비밀번호 변경은 아래 관리자 절차를 사용한다. 원격 MediaMTX 또는 수동 파일의 변경은 기존 수동 설정 절차를 사용한다.

연결 확인이 실패하면 성공으로 등록하지 않는다. 생성된 설정·보호 계정은 유지하며 같은 폴더와 포트로 재시도하면 재사용한다.
폴더를 다시 선택하면 저장된 자동 설정 포트를 불러온다. 수정된 설정 파일·손상된 복구 기록·보호 저장 접근 실패는 자동 재생성으로 대체하지 않는다.
설정 저장만 실패한 경우에도 기존 관리자·현장·영상 계정을 다시 만들지 않는다.

## 관리자용 로컬 영상 서버 비밀번호 변경

앱의 자동 설정으로 생성한 **ControlHost PC의 로컬 MediaMTX**를 관리한다. 다른 PC에서 접속한 관리자도 같은 호스트의 파일을 변경하며, 사용자 앱 PC의 파일을 수정하지 않는다.
수동 설정 파일·원격 MediaMTX는 기존 접속 정보 편집을 사용하고 해당 서버 설정은 별도로 관리한다. 자동 생성 파일이 외부에서 수정되었거나 누락되면 덮어쓰지 않는다.

1. 관리자 로그인 후 **사용 시작 → 카메라 · 영상 → 영상 서버 → 관리자 고급 설정 · 비밀번호 변경**을 펼친다. 호스트의 적용 설정을 자동으로 사용한다.
2. 변경할 **API 비밀번호** 또는 **HLS 비밀번호**를 입력한다. 각각 12~512자이며 서로 달라야 한다. 비워 둔 계정은 기존 값을 유지한다. 이 화면에서는 자동 설정의 주소·사용자 이름을 변경하지 않는다.
3. **호스트 영상 서버 비밀번호 변경**을 누르고 영상 처리 일시 중지 안내를 확인한다. 호스트가 변경 전·후 보호 참조를 DB에 먼저 기록한 뒤 설정 파일의 비밀번호 해시와 접속 정보를 함께 갱신한다.
4. **적용 확인 · API/HLS 인증**을 누른다. API/HLS 접근, 익명·상대 계정 접근 차단, 변경한 이전 비밀번호 거부와 확인 경로 정리를 검사한다. 확인이 끝나면 영상 경로를 재동기화한다.
5. 인증 적용을 확인할 수 없거나 영상 서버가 꺼져 있으면 MediaMTX 재시작 후 다시 확인한다. 앱이 시작한 서버는 시작한 앱을 정상 종료한 뒤 다시 열어 실행한다. 수동 실행한 서버는 관리자가 MediaMTX를 재시작한다. 이 기능은 실행 중 서버를 임의로 종료하지 않는다.

[MediaMTX 1.21의 파일 변경 감지·계정 갱신](https://github.com/bluenviron/mediamtx/blob/v1.21.0/internal/core/core.go)에 따라 실행 중 반영될 수도 있으므로,
파일 저장과 실제 인증 적용 확인을 구분한다. 이미 반영되었다면 재시작 없이 확인을 마칠 수 있다. 기존에 재생하던 영상의 자동 재개나 실제 카메라 입력 성공을 보장하지 않으며 필요하면 **재생 · 다시 연결**을 사용한다.

### 실패와 복구

- **파일 적용 다시 시도**: 파일 권한·잠금 문제를 해결한 뒤 같은 변경을 재적용한다. 이미 반영된 파일도 중복 계정 생성 없이 대조한다.
- **이전 설정 복구**: 변경 전 비밀번호로 설정 파일과 접속 정보를 복구한다. 복구 후에도 **적용 확인**이 필요하며, 서버가 이전 설정을 읽지 못하면 재시작한다.
- 앱 종료·호스트 재시작·응답 유실에도 미완료 변경과 이전 보호 계정을 보존한다. 다시 로그인해 사용권을 얻고 설정을 불러오면 이어서 확인·복구할 수 있다.
- 확인 전에는 새 비밀번호 변경·영상 재생·호스트 영상 재동기화를 중지한다. 다른 장비 작업과 기존 카메라·경로 정리 기록은 유지한다. 같은 서버의 정리 작업에는 갱신한 접속 정보를 사용한다.
- 변경·재적용·복구·확인은 모두 관리자 권한, 현재 사용권, 설정 버전과 변경 ID를 확인한다. 파일 적용 중 장애가 나면 성공으로 표시하지 않는다.
- 설정 파일에는 해시만, 일반 DB에는 보호 참조만 저장한다. 원문은 기존 DPAPI 보호 저장소에 보관하며 입력 필드는 작업 후 지운다. 적용 확인이 끝난 뒤 사용하지 않는 이전 보호 참조를 정리한다.

## 기존 데이터 연결과 위치 변경

1. 진행 중 작업을 확인하고 기존 로컬 호스트를 정상 종료한다. 앱이 시작한 호스트는 해당 앱 정상 종료로 끝낸다.
2. 폴더 이전이 필요하면 일관된 백업을 확보하고 **폴더 전체**를 이전한다. 실행 중인 DB만 복사하지 않는다.
3. 앱을 다시 열어 서버 시작 질문에서 **아니요**를 선택하고, **기존 데이터 사용**에서 기존/이전한 폴더를 선택한다.
4. **설정 저장 · 로그인으로**을 누른다. 호스트가 기존 DB·계정·보호 인증서를 확인한 뒤 경로와 접속 정보를 저장한다.

이 화면은 폴더 선택과 경로 변경을 제공하며 파일을 이동하지 않는다.
실행 중인 기존 호스트나 대상 호스트가 있으면 저장을 차단한다. 계정 ID·현장 ID·이력은 재생성하지 않는다.
다른 PC·Windows 계정으로 복사한 DPAPI 파일은 사용할 수 없을 수 있으며 자동 재발급하거나 초기화하지 않는다.

## 업데이트와 복구

- 설치/배포 버전이 바뀌어도 사용자 설정 폴더와 선택한 운영 데이터 폴더는 유지한다.
- 기존 App/server-startup.json은 사용자 설정이 없을 때 한 번 읽어 새 위치에 저장한다. 원본은 유지한다.
- 새 위치의 파일이 손상되었거나 백업만 남으면 과거 배포 설정으로 자동 복귀하지 않는다.
- 서버 설정 저장은 임시 파일과 원자적 교체를 사용한다. 정상 이전 값은 .bak, 손상 원본은 .damaged-*로 보존한다.
- **서버 설정 백업 복구**는 사용자가 선택할 때만 실행한다. 접속 설정의 백업 복구는 기존 로그인 화면에서 별도로 제공한다.
- 설치 프로그램은 사용자 설정을 생성하거나 덮어쓰지 않는다. 서버 연결·저장 위치 변경은 앱의 **초기 설정 · 저장 위치**에서 저장한다.
- 앱 제거도 운영 데이터와 사용자 설정을 보존한다.
- 검증용 --profile-dir은 전체 사용자 설정 루트를, --server-startup은 서버 설정 파일을 명시적으로 바꾼다.

필수 파일 확인은 준비 상태 검사다. 실제 DB 내용·보호 저장 접근·포트·네트워크 문제는 호스트 검사 또는 실행·접속 단계에서 드러날 수 있다.

현재 설치·첫 실행·재시도·비밀번호 변경과 데이터 보존의 검증 범위는 [배포 검증 기록](RELEASE_VALIDATION.md)을 따른다.
