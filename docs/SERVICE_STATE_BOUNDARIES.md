# 서비스 상태 접근과 공통 트랜잭션

## 변경 위치

`ControlService`는 기능을 조립하고 공개 호스트 API를 유지한다. 각 기능은 `HostAuthority` 대신
`FeatureStateContracts.cs`의 전용 포트를 받는다. 실제 `HostState`, 잠금 객체, 저장소와 전체 상태 저장은
`HostAuthority` 및 그 내부 구현인 `HostStateAccess.cs`에만 둔다. 전체 화면 조회용 `Snapshot`도 복사본이다.

| 기능 | 주입 계약 | 변경 가능한 상태 | 다른 기능에서 필요한 조회 |
|---|---|---|---|
| 장비 | `IDeviceStateAccess` | 장비 설정·상태, 역할·삭제 버전, 조명 배치, 불확실 장비 | 작업, 시나리오 정의, 계정 권한 복사본 |
| 시나리오·일반 작업 | `IScenarioStateAccess` | 시나리오 정의·삭제 버전, 접수 작업·실행 결과 | 장비 상태, 불확실 장비, 조명 배치, 현재 요청자 권한 복사본 |
| 영상벽 | `IHiperwallStateAccess` | Hiperwall 설정·편집·표시·저장 배치·슬롯 | 부모 작업, 시나리오 정의, 원 요청자 권한·세션 차단 여부 |
| 카메라 | `ICameraStateAccess` | MediaMTX 설정, 카메라, 경로 정리·보호 참조 삭제 큐 | 현장 ID와 인증·사용권·관리자 판정 |

다른 기능의 조회 컬렉션은 읽기 전용이며 항목의 중첩 상태도 복사한다. 예를 들어 영상벽에서 읽은 부모 작업의
`Steps`를 변경하거나 시나리오가 조회한 장비 상태의 사전을 변경해도 원본 트랜잭션에 반영되지 않는다.
계정 조회는 암호 해시가 없는 `AccountView`를 반환한다. 장비 해석 결과의 `StepSnapshot.Target`도 복사본이다.

## 트랜잭션 규칙

- `Change`는 공통 동기화, 호스트 정상 여부·연결 확인, 초안 생성, 단일 저장, 반환값 복사를 수행한다.
- 여러 단계의 동기식 확인이 필요한 코드는 `using (access.Open())` 안에서 `Current`, `Draft`, `Commit`을 사용한다.
  모든 포트는 동일한 호스트 잠금을 사용한다. 기능별 별도 잠금·별도 DB를 만들지 않는다.
- `Current`는 분리된 조회 복사본이다. 변경을 저장하려면 `Draft`가 필요하며 조회 복사본의 커밋은 거절한다.
- `StateContext`는 상태와 별개인 봉인된 토큰이다. 다른 기능의 상태 타입으로 변환할 수 없고,
  외부 기능은 자신에게 주입된 포트의 `For(context)`로 자기 상태만 얻는다.
  상태 범위 객체는 전달 시 이 토큰으로 변환되며 전체 `HostState`는 전달하지 않는다.
- 토큰은 발급 호스트, 현재 동기화 구간, 기준 상태 버전에 묶인다. 다른 호스트·종료된 구간·이미 저장한 문맥·
  중간에 다른 변경이 저장된 오래된 문맥은 거절한다. 임의로 생성한 토큰도 등록되어 있지 않아 사용할 수 없다.
- 같은 토큰에 참여한 기능의 변경과 감사 기록을 함께 한 번 저장한다. 검증 예외는 전체 초안을 폐기하고,
  저장 실패는 기존 메모리 상태를 유지한 채 모든 기능의 신규 작업·전송을 차단한다.
- 저장 직전 전체 초안을 복사하므로 서비스가 보관한 결과나 초안을 나중에 변경해도 저장된 상태는 바뀌지 않는다.
- `Open` 구간에 `await`를 넣지 않는다. 외부 통신은 구간 밖에서 기다리고, 새 구간에서 대상·설정·원 요청자 권한·
  작업 취소·호스트 저장 상태를 다시 검사한다. 토큰을 비동기 작업에 보관해 재사용하지 않는다.
- 인증·사용권·계정 변경은 호스트 권한 경계에 남는다. 사용권 반납은 접수 작업 취소가 아니며,
  원 요청자와 접수 snapshot, 불확실 명령 자동 재전송 금지 규칙을 유지한다.

## 기능 간 변경

시나리오가 장비 전송 의도·관측·불확실 상태를 기록할 때는 `IDeviceScenarioOperations`를 호출한다.
작업 저장과 장비 상태 저장은 같은 문맥에 참여한다.

`ScenarioJobLifecycle`은 부모 작업의 취소·단계 완료·표시 응답 대기 기록을 변경한다.
영상벽이 이 메서드를 호출할 때 부모 작업 ID와 토큰만 넘긴다.
미전송 표시 차단과 전송 중/불확실 여부 판단은 `IHiperwallJobLifecycle`을 구현한 `HiperwallJobLifecycle`에 둔다.
따라서 표시 결과와 부모 작업 차단은 함께 저장되며, 시나리오는 영상벽 전송 상태 컬렉션을 직접 받지 않는다.

호스트 시작 시 이전 세션 차단, 장비·작업 복구, 영상벽 표시 추적, 카메라 재동기화 예약도 하나의 트랜잭션이다.
복구 작업 중 일부만 저장된 상태로 시작하지 않는다.

## 복구 검토

영상벽의 검토 대상 선택과 변경 판정은 `HiperwallRecovery.cs`의 `DescribeRecovery`가 담당한다.
이 메서드는 편집·표시 복사본과 변경 지문을 반환한다. 호스트는 공통 작업·불확실 장비의 지문과 합쳐
검토한 사용자·사용권 세대·5분 유효시간을 검사한다.

재시도 예정 시각만 바뀐 경우 기존 검토를 유지한다. 전송 상태·정리 상태·시도 횟수·결과 메시지 등
검토할 증거가 바뀌면 다시 검토해야 한다. 복구 승인으로 작업을 취소하거나 자동 재전송하지 않는다.

## 검증

`FeatureStateBoundaryTests`는 기능별 변경 범위, 중첩 조회 객체와 장비 해석 결과의 격리,
문맥의 타입·호스트·수명·버전 경계, 계정 권한 복사, 여러 기능의 단일 커밋·저장 실패 취소,
재시작 복구의 원자성, 영상벽 복구 검토 유효성을 검사한다.

```powershell
dotnet test tests/IntegratedContro.Tests/IntegratedContro.Tests.csproj --filter "FullyQualifiedName~FeatureStateBoundaryTests|FullyQualifiedName~ServiceSeparationTests"
./scripts/verify.ps1
./scripts/publish.ps1
```

통신 중 설정 변경·취소·사용권 반납, 저장 실패 후 전송 차단, 재시작·교대와 화면 바인딩 회귀도 전체 검증에 포함한다.
공개 HTTP 요청·응답과 SQLite 상태 스키마는 변경하지 않는다. 격리된 로컬 호스트·가짜 장비 검증이며 실장비 검수와 구분한다.
