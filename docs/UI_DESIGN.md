# 화면 디자인과 공통 조작

2026-09-17 사용자 선택: **밝고 깔끔한 화면**을 기본으로 하고 다크 모드를 선택할 수 있다. 마우스와 터치를 함께 고려한다.

## 공통 기준

스타일의 기준은 `src/IntegratedContro.App/Theme.xaml`이다. 로그인, 장비·조명, 영상벽,
카메라, 시나리오, 교대, 관리자 설정에 같은 색상과 컨트롤을 사용한다.

| 요소 | 기준 |
|---|---|
| 배경·카드 | 옅은 회색 배경, 흰색 카드, 낮은 대비의 경계선 |
| 글자 | 맑은 고딕, 기본 14 DIP, 보조 설명 12 DIP, 진한 남색 본문 |
| 강조 | 청록색 선택 상태·주요 실행, 연한 빨강 삭제·전체 닫기 |
| 버튼 | 최소 48 × 48 DIP, 공통 여백·모서리·마우스 피드백·키보드 포커스 |
| 입력·선택 | 텍스트·암호·콤보·체크·탭 높이 최소 48 DIP |
| 목록 | 선택 행 48 DIP, 데이터 표 헤더 44 DIP |
| 슬라이더 | 높이 48 DIP, 손잡이 입력 영역 44 × 44 DIP |
| 스크롤 | 세로 터치 스크롤, Zone 바로가기는 가로 터치 스크롤 |

DIP는 WPF의 논리 단위다. Windows 배율에 따라 실제 화면의 픽셀 크기가 달라진다.
영상과 영상벽 캔버스에는 콘텐츠를 구분하기 위한 어두운 배경을 유지한다.
조명의 ON/OFF/알 수 없음은 상태를 나타내는 기존 색과 문구로 함께 표시한다.

버튼은 `ActionButton`을 기준으로 기본·`Primary`·`Danger`를 사용한다.
각 화면에서 별도 버튼 템플릿을 늘리지 않는다. 기능별 상태가 필요한 전원 선택과 조명은
공통 크기를 따르면서 상태를 추가한다. 입력·콤보·목록·탭은 기본 스타일을 사용한다.
선택된 탭의 글자색은 헤더에만 적용해 본문 전체에 상속되지 않도록 한다.

## 다크 모드와 전환

상단 계정·PC 정보 오른쪽의 **다크 모드 / 라이트 모드** 버튼으로 즉시 전환한다.
버튼 문구는 전환할 모드를 표시하며, 설명에는 현재 모드도 표시한다.
계정 권한이나 장비 사용권과 관계없이 사용할 수 있고, 선택한 탭·편집값·작업은 유지한다.

- `Themes/Light.xaml`, `Themes/Dark.xaml`에 동일한 이름의 색상 리소스를 정의한다.
  화면과 공통 컨트롤은 색상을 `DynamicResource`로 참조한다.
- `ThemeManager`가 앱 리소스를 교체하므로 이미 열린 화면과 새로 열리는 화면에 모두 적용된다.
  로그인, 입력·선택·목록, 조명 상태, 경고, 슬라이더·스크롤바·도움말도 같은 팔레트를 사용한다.
- 밝은 글자가 필요한 실행 버튼은 `AccentFill`/`OnAccent`, 일반 강조 글자는 `Accent`를
  사용해 다크 모드에서도 대비를 유지한다. 영상과 영상벽 캔버스는 기존 어두운 표시를 유지한다.
- 선택은 사용자 프로필의 `appearance.json`에 저장하며 다음 실행의 로그인 화면부터 복원한다.
  프로필 위치는 기존 `ClientProfileEnvironment`를 따른다. 접속 정보가 담긴 `client.json`과
  복구용 백업을 테마 변경으로 수정하지 않는다.
- 저장 파일이 없거나 읽을 수 없으면 라이트 모드를 사용한다. 저장에 실패하면 현재 화면에는
  적용하고 전환 버튼 아래에 이번 실행에만 적용된다는 안내를 표시한다.

테마 회귀 검증은 `--theme-only --profile-dir artifacts/ui-smoke/theme-profile`로 실행한다.
실제 전환 버튼, 최소 창 크기 배치, 글자 대비, 입력·목록 색상 갱신, 선택값 보존,
스크롤바 드래그, 저장 실패와 복구, 별도 프로세스의 실제 앱 시작·로그인 테마 복원을 확인한다.
`theme-dark-*.png`, `theme-light-restored.png`가 검증 화면이다.

## 밝기·음량

수동 장비 조작, 시나리오 편집, 영상벽 콘텐츠 음량은 같은 `TouchSlider`를 사용한다.

- 트랙을 누르면 해당 위치를 선택하고, 마우스 또는 한 손가락으로 연속 조절한다.
- 최소·최대값과 눈금 간격을 지키며, 놓는 위치까지 입력값에 반영한다.
- 두 번째 손가락, 캡처 상실, 비활성화, 화면 제거로 이전 제스처가 이어지지 않는다.
- 키보드 방향키로도 조절하며 값 바인딩은 유지한다.
- 슬라이더는 편집 중인 값만 바꾼다. 장비 전송·단계 저장은 기존 실행/적용 버튼으로 한다.
- 수동 조작의 숫자 입력을 병행한다. 잘못된 문자는 그대로 표시하고 실행을 차단한다.
  슬라이더의 범위 갱신이 잘못된 입력을 임의로 정상값으로 고치지 않도록 한다.

현재 제품 화면은 가로 슬라이더를 사용한다. 별도 세로 슬라이더를 추가할 때는
세로 트랙의 템플릿과 입력 방향을 함께 검증한다.

## 화면 구성과 작은 창

상단에는 앱 이름·현재 계정·PC와 모드, 하단에는 사용권 상태와 공통 동작을 배치한다.
주요 페이지는 여백이 있는 카드와 제목으로 구분한다. 로그인과 긴 설정 폼은 스크롤한다.
장비 목록은 최소 높이를 확보하고 아래 상세·역할 배정 영역을 따로 스크롤한다.

영상벽에서는 캔버스·Zone 이동·열린 콘텐츠 목록을 가운데에, 선택 편집·음량·전체 콘텐츠
조작을 오른쪽 스크롤 패널에 모은다. 작은 창에서 버튼을 축소하는 대신 편집 영역을
스크롤한다. 저장 슬롯은 상단에 유지한다. 기준 창 크기는 1500 × 1000 및 1180 × 860 DIP다.

## 확인 방법

```powershell
scripts/verify.ps1
dotnet run --project tests/IntegratedContro.UiSmoke -- --design-only --profile-dir artifacts/ui-smoke/design-profile
dotnet run --project tests/IntegratedContro.UiSmoke -- --editor-only --profile-dir artifacts/ui-smoke/editor-profile
```

전체 검증에는 공통 컨트롤의 실제 크기, 드롭다운 항목, 합성 WPF 터치 캡처·이동·놓기,
범위 제한·두 번째 터치·캡처 상실·비활성화 정리, 양방향 바인딩, 키보드와 RTL 검증을 포함한다.
수동 슬라이더와 숫자 입력 동기화, 입력만으로 명령을 보내지 않는 동작, 영상벽 편집과
최소 창 크기에서 목록·조작 버튼 접근도 확인한다. 화면 캡처는 `artifacts/ui-smoke`에 생성한다.

테스트는 격리된 가상 호스트와 가짜 Controller를 사용한다.
물리 터치패널, 실제 장비, 현장 디스플레이의 배율별 검증은 별도로 수행해야 한다.
