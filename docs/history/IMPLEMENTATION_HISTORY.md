### 앱 시작 시 서버 실행 확인과 앱 소유 서버 종료 (2026-09-18)

- ControlHost·MediaMTX를 확인하고 꺼진 서버가 있을 때만 실행 여부를 한 번 묻는다.
  이미 실행 중이면 질문 없이 로그인으로 진행하며, 하나만 꺼져 있으면 그 서버만 안내·실행한다.
  거절해도 로그인/접속 설정을 열고 서버를 시작하지 않는다.
- 최신 사용자 지시에 따라 그 앱이 직접 시작한 서버는 해당 앱 정상 종료 시 함께 종료한다.
  기존 실행 중 서버·다른 앱이 시작한 서버는 재사용만 하며 종료하지 않는다.
  다른 앱이 접속 중이어도 서버를 시작한 앱의 종료를 기준으로 한다. 사용 종료 버튼은 서버 종료와 별개다.
- LocalServerLifetime은 시작한 프로세스 핸들만 보관한다. ControlHost는 선택적 이름 있는 종료 이벤트로
  기존 StopApplication/Worker/소유 표시 정리 절차를 실행하고, 이어 소유 MediaMTX를 종료한다.
  호스트의 정상 종료를 최대 15초 기다린 뒤 남아 있는 소유 프로세스만 종료한다.
  종료 도중 늦게 완료된 시작 작업은 새 프로세스를 만들지 못한다. 강제 앱 종료는 정상 종료 처리와 구분한다.
- 설치별 경로만 담은 config/server-startup.local.json을 새 App/server-startup.json으로 배포한다.
  ControlHost는 동일 배포의 실행 파일, 기존 host.json·SQLite·보호 저장을 사용한다. 초기화/fallback DB는 만들지 않는다.
  현재 접속 주소·포트·인증서 지문을 대조하고 다른 프로필/원격 접속을 로컬 실행으로 대체하지 않는다.
  MediaMTX는 API 포트 소유 실행 파일과 응답을 확인하며 자격 증명을 복제하지 않는다.
- 상태 확인과 실행을 파일 잠금으로 직렬화하되 확인창 대기 중에는 잠금을 해제한다.
  승인 후 재검사하므로 동시 앱 실행으로 호스트를 중복 시작하지 않는다. 포트 충돌·파일 누락·설정 오류는 로그인 화면에 표시한다.

참고 파일은 frontend/events.html, events.css, events.js, wall-editor-geometry.js와
backend/src/hiperwall.js다. 원본 서버를 실행하거나 원본 데이터를 변경하지 않았다.

- 이름·경로·UUID·유형 검색, 콘텐츠 유형 필터, 응답 이름의 경로별 분류를 추가했다.
- 기본 list/walls에 더해 list action의 filter=open으로 열린 인스턴스를 별도 조회한다.
  이는 콘텐츠를 여는 명령이 아니다. fields 확장이나 버전 숫자 기반 기능 추정은 사용하지 않는다.
- 콘텐츠 UUID와 Instance/id를 분리한다. 같은 콘텐츠의 여러 인스턴스를 각각 표시하고
  이름이나 인접 Zone으로 대상을 매핑하지 않는다. Instance가 없는 Object 응답은 필터 미지원으로 표시한다.
- 실제 Zone left/top/width/height와 Instance position/size 응답으로 좌표 사각형을 그린다.
  참고 좌표 규약에 따라 Instance position은 중심, wire Y는 부호를 반전한다. 실제 버전 대조는 미검증이다.

- 확대·축소·전체 맞춤·선택 맞춤, 오른쪽/가운데 드래그 화면 이동, 항목 선택은 WPF 보기만 변경한다.
  캔버스는 좌표 영역이며 영상 프리뷰가 아니다. Wall 목록 미지원 시 가상의 Wall을 만들지 않는다.
- 새 인스턴스 목록·도형에도 기존 설정 버전, 중복 요청, 제한시간, 로그아웃·창 종료 정리를 적용한다.
- 빌드 경고/오류 0, 전체 테스트 107개 및 WPF 실행 검증을 통과했다. App/ControlHost self-contained 배포를 생성하고 Current에 반영했다.

### Hiperwall 연결·읽기 전용 조회 구현 (2026-09-09)

현재 단계는 단일 활성 Controller 설정, None/Token 인증, 읽기 전용 연결 테스트·목록 조회다.
Core 계약과 Application 권한·수명 로직, Infrastructure HTTP/XML·DPAPI 어댑터를 기존 프로젝트에 추가했다.
WPF는 기존 별도 HTTPS ControlHost API로만 접근하며 가상 조명·작업·교대 구조를 유지한다.
.NET SDK 10.0.400, 런타임 10.0.11과 기존 중앙 패키지·잠금을 유지하고 의존성을 추가하지 않았다.

- 관리자+현재 사용권+설정 버전으로 기존 SQLite에 연결 설정을 저장한다. 원문 토큰은 호스트 DPAPI에 격리한다.
  같은 대상·사용자에서만 토큰 재사용이 가능하며 설정/상태/감사 API는 비밀과 보호 저장 참조를 반환하지 않는다.
- GET /hello와 POST /xmlcommand의 기본 action list/walls만 지원한다.
  상세 공식 명세는 미확인이다. [프로토콜 근거](../HIPERWALL_PROTOCOL.md)에 공개 공식 자료·참고 코드·실제 접속 시도·미확인 항목을 분리했다.
- Contents는 Objects/Object의 기본 필드, Zone은 walls 요청이 Zones/Zone을 반환한 경우의 실제 필드를 표시한다.
  ID 없는 항목은 이름으로 확정하지 않는다. 비어 있지 않은 Wall 상세 목록은 필드·식별자 명세가 없어 미지원이다.
  별도 프로필·매핑에서 가짜 Wall/Zone/Contents를 생성하지 않는다.
- Hiperwall 전용 조회 탭과 관리자 설정 영역을 추가했다. 설정 없음, 확인 전/확인 중, 성공, 인증 실패,
  시간 초과, 연결 실패, API·형식 미지원을 구분한다. 실패 때 목록은 비우고 성공 시각은 별도 표시한다.
- 같은 세션의 중복 조회 차단, 요청 순서·설정 버전 재검사, 취소·제한시간, 로그아웃·창 종료 정리를 구현했다.
  호스트 상태만 조회하는 작업은 Controller 요청을 자동 반복하지 않는다. 읽기는 모든 활성 앱 계정에 허용하는 기존 정책을 따른다.
- 한국어 설정 변경·명시적 연결 테스트 감사만 기록하며 반복 조회는 감사 이벤트를 생성하지 않는다.
- XML DTD/외부 자원·리다이렉트를 차단하고 응답 크기·깊이·항목 수를 제한한다.
- 제공받은 http://127.0.0.1:8000에 /hello를 한 번 시도했으나 연결 실패했다.
  실제 버전·인증 성공·목록은 확인하지 못했다. 실제 Controller 호환성은 미검증이다.
- 콘텐츠 표시 변경, Crypto, Enhanced List, 전체 Semantic·카메라·영상·실장비 드라이버는 추가하지 않았다.
  이전 단계표의 Hiperwall 편집·표시 전체 완료로 간주하지 않는다.

운영은 [OPERATIONS.md](../../OPERATIONS.md), 검증·배포 결과는 [HIPERWALL_VALIDATION.md](../HIPERWALL_VALIDATION.md)를 따른다.

  구형 순서 전용 요청은 기존 그룹을 보존한다. 새 앱은 LightGroupsSupported를 확인해 그룹 미지원 호스트에서는 편집을 차단한다.
- 서비스/통합 테스트 46개 통과. 실제 WPF 창의 그룹 편집·저장·취소, 별도 HTTPS 세션의 저장 조회,
  합성 마우스 이벤트 차단·합성 WPF TouchDevice 캡처/해제 및 공통 드래그 경로를 검증했다.
  물리 마우스·터치 입력과 실제 두 PC 검증으로 보고하지 않는다.
- 최신 배포 위치를 artifacts/publish/Current/App 및 Current/ControlHost로 통일했다.
  기존 데이터 폴더를 그대로 지정해 새 호스트를 실행한다. 사용자 실행 중인 앱/호스트와 운영 DB는 변경하지 않았다.
- Git 점검에서 기존 *.app 제외 규칙이 WPF 프로젝트 폴더까지 제외함을 확인했다.
  src/IntegratedContro.App/ 예외를 추가해 소스가 누락되지 않게 했다. bin/obj와 기존 docs 제외 규칙은 유지했다.

접속 팝업·감사 기록·일괄 조명 후속 구현(2026-09-09):
- MainWindow에서 접속 입력 영역을 제거하고 시작 시 소유 모달 LoginWindow에 주소·SHA-256 지문·앱 계정·비밀번호를 표시한다.
  접속 실패 시 팝업을 유지하고 성공 시 닫는다. 비밀번호는 저장하지 않으며 시도/닫기 후 비운다.
  우측 위 작은 로그아웃 버튼과 미로그인 접속 버튼을 제공하고 로그아웃 후 팝업을 다시 표시한다.
- '호스트 계정'은 기존 Administrator 권한으로 해석했다. 관리자 설정 탭은 관리자 로그인 때만 표시하고,
  로그아웃/권한 상실 시 선택된 관리자 탭에서 벗어난다. 호스트의 기존 관리자+사용권 쓰기 검사도 유지한다.
- AuditEntry에 사용자 이름·한국어 이벤트 이름·설명을 추가한다. 새 기록은 발생 시점에 해당 표시 내용을 저장하고,
  기존 기록은 원본을 보존한 채 조회 시 해석한다. 기존 작업 설명은 불변 snapshot을 참조하고,
  이름을 기록하지 않았던 설정 이벤트는 현재 등록 이름을 참고한다. UI는 현지 시각·사용자·동작·내용과 원본 상세를 제공한다.
- 조명 전체/그룹/미분류 ON/OFF는 LightBatchRequest로 대상 전부와 실행 내용을 고정해 한 트랜잭션으로 접수한다.
  목록·그룹 버전/범위/역할·장비 버전/PC ID/확인 상태/예약·남은 작업/권한·사용권 중 하나라도 맞지 않으면 접수 전체를 거부한다.
  일부 장비 자동 제외나 단순 토글은 하지 않는다. 현재 ON 상태에 ON을 요청해도 절대 Power=1을 유지한다.
- JobKind.LightBatch의 순차 작업으로 저장하고 기존 Worker의 각 단계 전송 재검증·실패 중단·취소·보존 흐름을 적용한다.
  접수 한도는 1~1000개, 만료는 5분이다. 새 그룹 구성은 접수된 snapshot을 변경하지 않는다.
  작업이 남아 있는 대상의 충돌 수동 조작을 막고, 사용 종료 후에도 원 요청자·작업을 유지한다.
  다음 사용권자의 대상 전체 권한을 검사해 남은 단계를 선택 취소한다. 전송한 동작을 정지·롤백으로 표시하지 않는다.
- 재시작 시 아직 전송하지 않은 일괄 작업만 재검증 후 진행할 수 있다.
  전송을 시작한 일괄 작업·불확실 결과는 자동 재개/재전송하지 않는다.
  LightBatch를 모르는 구형 호스트는 새 작업을 일반 명령으로 오인하지 않고 역직렬화에 실패한다.
  기존 DB는 최신 호스트에서 그대로 유지하며 신규 API 지원 표시는 LightBatchSupported로 제공한다.
- SDK 10.0.400 재확인, 테스트 59개 통과, Release 빌드 경고/오류 0.
  실제 WPF 팝업 입력/실패/성공/로그아웃, 관리자 탭 숨김, 전체/그룹 ON/OFF, 감사 화면 및 기존 흐름을 로컬에서 검증했다.
  물리 터치·실제 두 PC는 미검증이다. 최신 배포는 Current/App 및 Current/ControlHost다.

주요 구현 결정:

- Core/Application은 WPF·레지스트리·Win32·COM·SQLite 구체 구현을 참조하지 않는다.
  가상 드라이버/SQLite/보호 저장/호환성 판정은 Infrastructure, 클라이언트 OS 설정은 App에 둔다.
  WindowsDevices/영상/DeviceAgent 등 불필요한 빈 프로젝트는 만들지 않았다.
- 초기 저장은 소규모 현장용 SQLite 상태 aggregate와 보존 감사 이력을 같은 트랜잭션으로 저장한다.
  전송 시뮬레이터의 값도 SQLite에 보존한다. 저장 실패는 신규 제어를 차단하며 메모리 성공 응답이나 다른 DB fallback을 하지 않는다.
- 정상 교대는 기존 작업을 계속 실행한다. 호스트 재시작 시에는 미전송 일반 명령만 재검증 후 실행할 수 있고,
  전송 여부가 불명확한 명령과 중단 시나리오는 자동 재실행하지 않는다.
- 초기 공유 설정·계정 변경은 관리자 권한과 사용권을 모두 요구한다. 운영자는 범위 내 제어·이전 작업 취소,
  조회자는 조회만 가능하다. 사용권 없는 STOP 우회는 제공하지 않는다.
- 첫 조건 검사는 단계 실행 시 최신 가상 상태를 한 번 조회해 비교한다. 조건 충족까지 반복 대기는 후속 기능이다.
  대기 값/기능/역할은 현장별 정의로 구성하며 예시 운영 절차를 고정하지 않는다.
- 개인 키는 현재 Windows 계정 DPAPI로 보호한다. Windows Schannel에서 ephemeral key가 거부되는 것을 실제 통합 테스트로 확인해
  실행 시 보호된 사용자 키 저장소에 로드한다(영구 유지 플래그 없음).
  근거: [Microsoft SslStream 진단](https://learn.microsoft.com/en-us/dotnet/core/extensions/sslstream-troubleshooting).
- 최초 자체 인증서 유효기간은 2년이며 지문을 통해 현장에서 접속 대상을 확인한다.
  인증서 갱신, 관리자 비밀번호 분실 복구, Windows 실행 계정 변경/보호 저장 이관은 후속 운영 도구로 남긴다.
- 서비스 등록, 자동 실행, 방화벽 변경, 실제 장비 쓰기, Hiperwall·실제 영상·Semantic은 수행하지 않았다.

실행 방법은 [운영 절차](../../OPERATIONS.md), 실행한 검증과 미검증 항목은
[첫 구현 검증 기록](FIRST_IMPLEMENTATION_VALIDATION.md)을 따른다.
개발·배포 스크립트는 `scripts/verify.ps1`, `scripts/publish.ps1`이다.
